Daily editorial copy (rdj-editorial-copy-v2, archived v1 compatible)

The optional v2 batch editorialCopy contains a distinct contextual description
and short notification for each source event, in French and English. Gemini
receives the complete FR source context and returns choice.entries with exact
ordered source IDs. Node checks the same factual hash, labels, entry structure
and deterministic rendered bodies as the shared hub. Source paragraphs,
summaries, selections, odds and item payloads are never rewritten by this copy.

The v2 envelope adds notificationBody; choice uses angle:context, focusIds for
ALL source IDs, and entries:[{id,description:{fr,en},notification:{fr,en}}].
Descriptions allow 180 Unicode code points per hook, notifications 90. Aggregate
display keeps a fitting prefix plus +N other-event suffix, with UTF-8 budgets
of 1800 bytes for body and 900 for notificationBody. Exceptionally long first
labels are safely shortened for display only. Every ID and entry remains bound
in the envelope. The API drops an invalid optional v2 copy and imports the valid
source batch normally; no semantic or word-count quality gate is introduced.
Generation failures use a source_excerpt_fallback or omit the optional copy.
The archived v1 renderer, fallback, validation and historical fixtures retain
their exact previous behavior.

Provision BEFORE activating the new import code, from the reviewed checkout:
  node tools/editorial-indexes.cjs --copies-only --check
  node tools/editorial-indexes.cjs --copies-only --apply --confirm-editorial-indexes
The default is read-only. The explicit apply creates only editorialcopies and
its unique {appId,source,editionDate} index, without modifying any historical
collection, record or index. Index conflicts require review; no drops occur.

Imports require a replica set with sessions/transactions (verified separately
by the deployment operator). A deterministic wintips:source:date lock is created
only in the explicitly provisioned collection. The revision lock, first copy
decision and all article writes then share one snapshot/majority transaction.
The ticket families retain their existing additional edition lock in that same
transaction. A failed transaction may leave an empty uninitialized lock, never
a committed copy or partial articles.

ANY existing article for the source/day, including an unpublished/archived
mapping, or ANY old WinTips notification ledger makes the first decision null
and legacy. Publication without an envelope likewise freezes null. Reimports
cannot retrofit or replace it. No migration of old days is performed.

GET worker config exposes editorialCopyState:{state:new|frozen|unknown,legacy}
per source for the CURRENT Europe/Paris edition. This read creates no records.
Only new/non-legacy may request hooks; frozen/unknown omit generation. A new
day naturally starts independently. Missing/unavailable storage yields unknown.

The feed adds localized editorialDescription only when all original article
IDs, full payload hashes and copy facts still match. Library/native edition
cards prefer bound v2 descriptions before the existing contextual source
excerpts. Older editions retain their existing excerpt/copy fallback order.
Stored category BO text and item summaries are unchanged. A changed/partial
batch hides stale cosmetic copy rather than generating a replacement.

On the FIRST notification ledger insert only, freeze editorialCopy (or null),
its SHA and the exact eligible, ordered item hash. Pending/completed/legacy
ledgers are never retrofitted. A changed new snapshot enters review_required
before any send. Delivery uses notificationBody when present, otherwise the
original v1 body. Existing notification ID, device deduplication, opt-in, language,
entitlement and delivery retry policies remain authoritative. No extra send is
triggered by reads or this cosmetic feature.

Offline tests:

  node --test tests/editorial-copy-v2.node-test.cjs
  node --test tests/editorial-copy.mongo-test.cjs
