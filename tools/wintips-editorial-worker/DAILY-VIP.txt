WinTips — Combiné du jour (pilot, 17 November 2026)
==================================================

The new source is wintips_daily_vip. It produces ONE native coupon, not a
journal/article and not an HTML document. No AI generation or translation is
used. Only explicit SportyTrader editorial conclusions are eligible; their
automatic probability table is deliberately not interpreted as advice.

Discovery:
  https://www.sportytrader.com/pronostics/aujourdhui/

The day index is discovered again on subsequent attempts until the API proves
that the day's coupon is frozen. Sport sections are visited round-robin, with
16 event pages at most. A French prediction page must identify exactly two
participants, a supported sport and a dated hero clock. The corresponding
odds URL must be explicitly linked by that prediction page. Its own participant
identities, competition, sport and clock must all agree with the prediction.
French clocks are interpreted as Europe/Paris and converted to UTC. Ambiguous
DST times are skipped. Each leg must start more than 30 minutes in the future.

Supported v1 markets:
  - full-match participant winner;
  - football full-match over/under 1.5, 2.5 or 3.5 goals;
  - football both teams to score, only when the named market is present.

Other recommendations (handicaps, half-time bets, complex conditions, etc.) are
skipped. A new sport can use the common winner adapter only if its source
market has unambiguous 1/2 columns. No unrelated price is substituted.

Composition policy:
  - 2 or 3 distinct fixtures, without a participant appearing in two legs;
  - one named bookmaker shared by ALL legs;
  - raw decimal product in [3, 3.5], then rounded to 2 decimals;
  - deterministic choice closest to 3.25 (tie: fewer legs, then bookmaker/IDs).

This ranking is a composition policy, NOT an estimated success rate. It does
not promise 5 wins in 7 days. The optional exceptional ceiling of4 is not
  enabled in v1. If no verified combination fits, no coupon is published and a
later run retries. No invented market, fabricated price or stale fallback.

Observed prices are timestamped using the actual HTTP observation (also when
cached). Collector freshness is15 minutes. Source URL hashes stay in the run
report. Prediction URLs, exact market text, odds URLs, bookmaker and timestamps
stay in the compact payload. No publisher analysis or HTML is stored in Mongo.
Settlement is explicitly pending; this module does not infer won/lost from a
publisher's later changes. A verified results adapter is separate future work.

Scheduling and resource limits:
  This source is EXPLICIT ONLY: --source wintips_daily_vip. Legacy RDJ default
  runs exclude it. Use the dedicated timer and the same state output directory
  to share the existing single-run lock. Maximum33 GETs (1 + 16 + 16), using
  the fetcher's global timeout/request budget. Suggested dedicated budget:
  --max-requests 40 --max-seconds 240 --cache-ttl-seconds 600.
  SportyTrader HTTP cache is isolated under http-cache/sportytrader, pruned
  after2 days and capped at80 MiB. It does not prune RDJ caches. RAM only lasts
  for the bounded oneshot process; no models, images or new dependency.

Local read-only preview (no API changes, notification or publishing):

  python -B -m editorial_worker --source wintips_daily_vip --dry-run \
    --output ./var/daily-vip-preview --max-requests 40 --max-seconds 240

Authenticated configuration/publishing uses the existing /api/internal/
editorial/config and /import. A configured source.dailyVipState of 'new'
permits collection; 'frozen' with the canonical sourceId skips all HTTP work.
Unknown/review_required state stops this source. The API also freezes the
first valid daily composition transactionally, including concurrent attempts.
Publishing requires an explicit --publish and a reviewed API release. The
pilot category is linked to Black Friday; public catalogue previews must not
expose leg selections. Automatic notifications are disabled for this pilot.

Tests:
  python -B -m unittest tests.test_daily_vip

Fixtures are minimal real SSR fragments captured on17 November2026. Tests
cover authored-vs-automatic disagreement, exact market columns, wrong event,
same bookmaker, decimal boundaries, timestamps/DST, immutable snapshot,
native bilingual labels without model calls, and the actual Node API schema.
